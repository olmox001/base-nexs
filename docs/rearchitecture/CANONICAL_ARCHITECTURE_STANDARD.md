# Integrated NEXS Architecture Standard — NXEC / NXOLMO / Base-NEXS

Status: normative architecture and source migration contract, NOT a claim
that the entire engine has been reimplemented.

Base-NEXS is the ONE product. NXEC, NXOLMO and Base-NEXS are **roles**,
not separately linked runtimes. Their repositories can be compared as
read-only design/source evidence; the finished product is independently
buildable and runs without them. Canonical ownership must be enforced
function-by-function, not by replacing complex algorithms with stubs.

The autogenerated CANONICAL_FUNCTION_OWNERSHIP.csv assigns exactly one
target role and module to each of the 4,588 currently indexed definitions.
Every row retains its original source, symbol, path, source line, phase
gate and implementation evidence. Classification does NOT establish that
each function is reviewed or migrated. No old caller may remain attached
to an obsolete implementation after its canonical replacement is accepted.

## Canonical ownership boundaries

| Role | Single authoritative scope | Forbidden duplication |
| --- | --- | --- |
| Shared ABI | status/result, spans, checked math, endian, cryptographic primitives, object IDs and serialization | per-role ABI forks, new status schemes |
| NXEC boot | UEFI/Multiboot2/ACPI/DTB memory maps, HCD builder/parser, trust handoff and separate kernel admission | runtime registry and application semantics |
| NXEC HAL/kernel | CPU/IRQ/timer/frame/map/device primitives, object authority enforcement, kernel faults | userland process catalogs, kernel POSIX and VFS |
| NXEC REG transport | endpoint sessions, versions, envelopes, sequence, correlation, cancellation, credit/backpressure and capability handle transfer | second registry, marshaling raw pointers |
| NXOLMO object | stable ID+generation, schema/type, parentage, lifecycle, ownership and object references | application identifier tables |
| NXOLMO registry | ONE name+object index, state revisions, snapshots, MVCC, schema migrations, transactions | RegKey shadow tree or global callable/array tables |
| NXOLMO authority | principals, capability issuance/validation, delegation, attenuation, revocation and commit-time rechecks | trusting caller-supplied rights |
| NXOLMO memory | resource-admitted arenas and page providers, leases, pin/map, checked zero-copy descriptors and reclaim | fixed global allocations, independent page-lookup tables |
| NXOLMO storage | block, WAL, ext4, 9P, unified VFS object graph and durable recovery | duplicate file/9P implementations |
| Base-NEXS language | exact lexer/source spans, parser, types, effects, AST->verified IR | separate hosted vs AOT semantics |
| Base-NEXS compiler | one IR verifier, linker, native and portable backends | separate hardcoded source lists |
| Base-NEXS runtime | per-instance namespace, scheduler, VM frames, tasks, budget, exception and module graph | global fn_table, global runtime stack, unbounded C recursion |
| NXEXEC | executable image, owner/ctty/process/job/supervision/capability transfer | kernel hardcoded process identity or new syscalls |
| Adapters | target-specific entrypoint and hardware/service ABI mapping | platform-specific copies of the core algorithms |

All public exposed functions and objects resolve through NXOLMO identity,
type/schema, generation and authority. Registry path lookup does not grant
rights. In-process dispatch can cache validated callable slots; REG is
solely transport, never another state store. Only leases with checked
rights, owner, generation, page alignment and cache coherence qualify for
shared zero-copy arrays; otherwise transport must copy into checked bounds.
All resource limits are admitted provider budgets, not arbitrary ceilings.

## Authoritative source migration (no reduction of functionality)

- NXEC: port preboot/common HCD CRC64, schema/sections, parser/semantic
  verifier, builder and memory planner; preboot/hal ISA, UEFI, Multiboot2
  map normalization; independent kernel/core/hcd parser and admission.
  Preserve all adversarial and separate-trust-domain tests.
- NXOLMO: port base checked/status/result/types/endian (completed),
  crypto and clocks; StateStore/nxreg/schema/migration/snapshot pool,
  capability and hardware auth, buffer/lease/capability adapter,
  budgets/metrics, block/journal/WAL, full ext4 and 9P protocol.
  The imported Linux 9P snapshot is NOT a ready-made product and must
  undergo licensing, algorithm comparison and Power12 review.
- Base-NEXS: migrate core buddy/pager/value/array, registry and reg_ipc,
  language fn_table/parser/eval/builtins, compiler/codegen/dep_scan,
  runtime/TTY, sysio/sysproc, fs and kernel/HAL callers to their one
  canonical owner. Delete each obsolete implementation after migration.
- NXEXEC: integrate the reference OS1 SDK execsvc and nxexecd semantics
  for owner/capability, CTTY/focus, argv/env/cwd, foreground/background,
  cancellation, failure result and supervision. OS1 remains read-only.

## Standard destination ownership tree

    core/                 shared C ABI, checked, status, types, crypto
    boot/hcd/             NXEC boot HCD and independent admission
    boot/hal/             NXEC hardware discovery and memory maps
    hal/                  NXEC architecture provider
    kernel/               NXEC minimal object-capability hardware kernel
    transport/reg/        NXEC REG sessions and encoded messaging
    state/object/         NXOLMO generational object graph
    state/registry/       NXOLMO ONLY canonical registry and callables
    state/authority/      NXOLMO principals and authority
    state/memory/         NXOLMO arenas/frames/buffers/leases
    state/storage/        NXOLMO block/WAL/ext4/9P and VFS
    language/             Base-NEXS language frontend and semantics
    compiler/             Base-NEXS one IR/AOT/VM linker
    execution/runtime/    Base-NEXS concurrent runtime and VM
    execution/execsvc/    NXEXEC process and terminal ownership
    nxlib/                one .nx language libraries and services tree
    nxlib/services/       programmable NEXS userland services/drivers
    extensions/           native C runtime/userland modules, one owner
    tests/                per-function proofs and full guest tests

These are destination contracts, NOT incomplete stub libraries or new
duplicated implementations. Existing core/, registry/, lang/, sys/, fs/
and kernel/ remain migration inputs until all callers have moved to a
replacement that covers their entire behavior. Every file move must be
paired with API ownership and call graph update, not just a rename.

## Phase acceptance: strict and falsifiable

Each migrated function needs success and fault/negative tests, call graph
resolution, source ownership and tests on supported host/freestanding
targets. Trusted code enforces Power12 (no goto/break, unbounded loops,
hardcoded timings, or unsafe asserts). No compliance exemptions.
Kernel has no new syscalls, process catalogs or POSIX VFS.

Full acceptance requires: all relevant reference behavior preserved,
NEXS runtime and AOT semantic agreement, multiple independent concurrent
instances, bounded continuation frames, typed OOM and cancellation,
capability revocation, zero-copy lease tests, WAL recovery, full 9P/ext4,
real QEMU boots + nxadb interaction on AMD64/AArch64 and clean Power12.
The external umbrella's missing doom.mk currently blocks nxadb boot;
this is NOT counted as a pass.

## Current verified boundary

core/include/nexs_checked.h, core/checked.c and core/status.c implement
the COMPLETE existing checked arithmetic/span/status, types, result,
and endian contract, including 25 status codes, 27 functions and inline
codecs. 57 checked and 39 foundation positive/negative ABI checks and
AddressSanitizer/UBSan pass; the product build has no NXOLMO link/include.
These 27 functions are the only ones currently marked as completely ported
in the canonical function ownership ledger.

The language's old g_fn_table was then removed: the existing RegKey
registry now directly owns functions at /fn/ and builtins at /sys/ with
Value-driven reference lifetimes. This is a tested elimination of the
duplicate name index, NOT the final NXOLMO StateStore, generational ID
and cross-process authority migration. Raw callables remain local and
are not valid REG/IPC serializable function IDs.

All other NXOLMO/NXEC source functions remain NOT PORTED or REFERENCE.
The unfinished pager still has global mapping records and fixed physical
RAM profiles, so it is NOT the final NXOLMO page/object provider; it
must not be certified as completed. Base-NEXS runtime global registry,
VM recursion, ABI/capability trust and WAL/VFS remain unresolved.


## Pre-P4 actual placement

All .nx libraries and services now live in nxlib/ and
nxlib/services/; no services or modules copy remains. The actual
native text-buffer extension resides in extensions/textbuf and
registers through the existing one callable registry. This is
NOT a full NXOLMO StateStore or REG migration.
See PRE_P4_HARDENING_CHECKPOINT.md for precise verification and
unresolved Plan 9, NXEC and NXEXEC blockers.
